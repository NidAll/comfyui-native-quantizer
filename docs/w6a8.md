# Native W6A8

`--format w6a8` (alias `w6a8_int8`) emits ComfyUI's native six-bit weight / INT8
activation format. Conversion requires **comfy-kitchen 0.2.36 or newer** with
explicit `bits` and `scale_search` parameters. Loading requires **ComfyUI 0.38.0
or newer** with `w6a8_int8` registration. An older W4A8 layout accepting arbitrary
keyword arguments does not establish six-bit support.

The implementation uses Kitchen's public API with `bits=6`, symmetric uniform
quantization, FP8 E4M3FN group scales, `codebook=False` and scale search enabled.
Conversion defaults to FP32. The algorithm and installed Kitchen version are
recorded in the output.

## Commands

```bash
comfyquant --no-config model.safetensors \
  --format w6a8 --w6a8-group-size 16 \
  --output model-w6a8.safetensors --max-memory 512M --validate

comfyquant --no-config model.safetensors \
  --format mixed --enable-w6a8 --w6a8-group-size 16 \
  --output model-mixed.safetensors --max-memory 512M --validate

comfyquant --no-config --verify-output model-w6a8.safetensors
comfyquant --no-config model.safetensors --format w6a8 \
  --output model-w6a8.safetensors --validation-only
```

Mixed mode keeps W6A8 **disabled by default**. Existing profiles retain their
candidate sets unless `--enable-w6a8` is supplied. This flag is mixed-only.

Group size defaults to **16**. Positive multiples of 16 are accepted when they
divide the layer input width K. The converter requires **K divisible
by 256**, with ConvRot width 256. It never pads checkpoint dimensions. Architecture
policies continue to protect input/output projections, normalization, modulation
and embeddings; unsupported tensors retain source precision.

## Tensor contract

For a weight `[N,K]` and group size G:

| Tensor suffix | Storage |
| --- | --- |
| `.weight` | INT8 container `[N,3K/4]` |
| `.weight_s_rel` | FP8 E4M3FN `[N,K/G]` |
| `.weight_s_channel` | FP32 `[N]` |

Each packed row contains K/2 bytes of low four-bit codes, followed by K/4 bytes
of upper two-bit codes. Adjacent low codes occupy low/high nibbles; four upper
codes occupy bit pairs 0–1, 2–3, 4–5 and 6–7. No codebook or correction tensor is
allowed. Metadata records `format=w6a8_int8`, the selected group size,
`convrot=true` and `convrot_groupsize=256`.

For prefixed checkpoints, layer configurations are stored in native UINT8
`.comfy_quant` tensors; `_quantization_metadata.layers` is empty. ComfyUI moves
those configurations together with the weights when removing the prefix, avoiding
duplicate unexpected keys. Bare checkpoints retain header layer configurations.
The verifier and validation-only mode read both representations.

Independent decoding subtracts 32 from the six-bit code, applies the FP8 group
scale, rounds/clamps to signed INT8 `[-127,127]`, applies the channel scale and
inverts the rotation. Runtime calibration scoring includes activation rotation
and dynamic INT8 quantization, then scores the scaled integer product.

Payload size is exactly **N(3K/4 + K/G + 4)** bytes, excluding metadata and
passthrough tensors. At G=16 this is **0.8125 + 4/K bytes per weight**. Conversion
uses a conservative 160-byte-per-element working estimate for row budgeting,
or 256 bytes per element with MSE optimization. This includes scale-search tables
and temporaries; it estimates the working set and does not guarantee measured
model VRAM. Chunked jobs require at least 32 MiB.

W6A8 shares streamed writing, source preservation, atomic publication, reports,
calibration ingestion, sensitivity gates, validation and resume integrity with
the planned execution engine. Optional [MSE optimization](mse-optimization.md)
refines scales on the native six-bit/INT8 grid, retaining the Kitchen seed when
no valid candidate improves the objective. Resume identity includes group size,
Kitchen version, algorithm revision and conversion budget. Identical options on the same backend
and version are checked for repeatable payload bytes. Across chunk budgets use
numerical comparisons: FP32 channel-scale reductions can differ slightly.

## Runtime and costs

Six-bit storage decodes onto the INT8 execution grid. General GEMM may allocate
an INT8 decode workspace; small-batch fused paths can avoid it. W6A8 has a separate
capability and certificate entry, even though it uses `AsymW4A8Int8Layout`.

`quantizer-kitchen-benchmark` measures W6A8 alongside existing formats and emits
**kitchen-costs/v2**. Group size is part of each grouped format's cost key.
The planner still accepts v1 costs for previous formats, never for W6A8.
Measurements only apply to the matching Kitchen version, weight shape,
activation precision and group size, with the recorded M workload.

```bash
quantizer-kitchen-benchmark --n 64 --k 256 --m 64 --repeats 10 \
  --w6a8-group-size 16 --comfy-root /path/to/ComfyUI > kitchen-costs.json
```

The probe reports first/warm timing and temporary allocation peaks separately.
These are synthetic linear measurements, not full-model speed or memory claims.

The tested Kitchen CUDA eager fallback can execute odd output-row counts.
In the tested larger-batch odd-row case, that fallback creates an unpinned CPU
shift tensor during decoding, so CUDA graph capture fails. Aligned-row cases
pass native forward and graph replay. The converter preserves odd dimensions;
it does not patch Kitchen or silently pad the checkpoint to change dispatch.

## Validation

```bash
comfyquant --no-config --self-test
python -m unittest -q tests.cpu.test_quantizer_native tests.cpu.test_kitchen_pipeline \
  tests.cpu.test_w6a8
# Run separately where CUDA is visible:
python scripts/check.py --comfy-root /path/to/ComfyUI --cuda
```

Fixtures cover bit boundaries, zero-valued rows, ordinary/heavy-tailed weights,
groups 16/32/64, odd row counts, protected tensors, mixed opt-in and promotion,
calibration gates, malformed metadata/scales, real bounded streaming, interrupted
resume, failed publication, CLI/worker payload parity and native ComfyUI
load/save/device movement. CUDA tests use published synthetic checkpoints and
record the odd-row graph limitation separately. No large model is downloaded or
converted. Full-model image quality, throughput and peak memory remain unmeasured.

ComfyUI-dependent checks require an explicit `COMFYUI_ROOT`. Without it, default
unit checks skip consumer integration. The CUDA command above requires its
consumer and backend and fails when either is unavailable.
